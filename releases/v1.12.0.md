# Menditect Agent Workspace Template - Release Notes

## Version v1.12.0

> Released on: 2026-11-09

### Release Summary
new workspace configuration options available. One central template hub with multiple app specific workspaces

---

### Detailed Changes
- Added **3 Workspace Architecture Options** in `npm run setup`:
  1. **`[1] Central Tools Hub — Multi-App / Shared Engine` (`workspace_type: "custom"`):** Keeps `skills/`, `tools/`, and `bin/` strictly in the central `agentic-test-workspace` repository with zero file duplication and zero symlinks. Multiple lightweight app workspaces point directly to the central hub for single-point `npm run update` maintenance.
  2. **`[2] Standalone Subfolder Workspace — Single-App Isolated` (`workspace_type: "clone_root"`):** Copies `skills/` and `tools/` into the parent workspace folder for single-app version isolation.
  3. **`[3] Direct Mendix Project Workspace — In-Repo Collaboration` (`workspace_type: "mendix_project"`):** Places configuration, skills, and execution plans directly inside the Mendix `.mpr` folder.
- Added automated **Workspace Setup Model Switching** in `scripts/setup.js`, including auto-hydration of existing `mta_config.json` / `.env` files, `menditect-output/` execution plan migration, and cleanup of redundant local copies.
- Updated `scripts/sync-upstream.js` so `npm run update` updates `skills/`, `tools/`, and `bin/mxcli` in-place inside the central hub when using Option `[1]`.
- Updated `scripts/mta-proxy.js` and `scripts/verify-setup.js` to prioritize active per-app workspace configurations (`process.cwd()/mta_config.json`) and resolve central `tools_dir` / `tools_root_dir` paths.
- Documented the 3 workspace setup options and model-switching workflows in `README.md`.
