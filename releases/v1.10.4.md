# Menditect Agent Workspace Template - Release Notes

## Version v1.10.4

> Released on: 2026-10-06

### Release Summary
added linter support for validation feedback asserting (PAT-119, ANTI-20)

---

### Detailed Changes
- **Frontend Event-Driven Validation Feedback Linting (`PAT-119`, `tools/mta-lint.mjs`)**:
  - **Widget Locator-to-Validation Message Type Map**: Enforces strict parameter mapping across all 7 supported Menditect Frontend TestKit widget types (`TextBox`, `DropDown`, `DatePicker`, `ReferenceSelector`, `ComboBox`, `CheckBox`, `RadioButtons`).
  - **Handle Chaining & Anti-Orphan Check**: Verifies that every `Locate_MxWidget_*_ValidationMessage` output handle is immediately piped into an assertion step (`ASR_Is_Hidden_MxLocator` for nominal/happy path or `ASR_Is_Visible_MxLocator` / `ASR_Has_Text` for negative fault-injection), flagging orphaned locator handles.
  - **Mandatory Intent & Trigger Documentation (`PAT-12` / `PAT-119`)**: Requires that each validation locator and assertion step contains a clear `Description` documenting the event trigger (`onChange` on leave, `onChange` while typing with delay, `onEnterPress`, or `Save`/`Submit` button) and the flow origin (Microflow or Nanoflow AST).
  - **ANTI-20 Frontend Isolation Enforcement**: Rejects backend validation assertion calls (`CreateAssertValidationFeedbackMessage*`, `Assert Validation Feedback Count/Compare`) in `category: "Frontend"` test plans.
- **Enhanced Smoke Audit (Phase 6b Parity)**:
  - Added **Phase 6b: Frontend Validation Feedback Assertions** to verify that server-side validation steps retain documented event/flow rationale and parameter wiring.
- **Fixture Suite & Self-Test Expansion**:
  - Added test fixtures in `tools/fixtures/`: `valid_frontend_validation_feedback_plan.md`, `invalid_frontend_orphaned_validation_locator.md`, `invalid_frontend_wrong_locator_type.md`, and `invalid_frontend_backend_assert_in_ui.md`.
  - Expanded internal linter self-test suite to **21/21 passing checks**.
- **Synchronized Skills**:
  - Synchronized updated skill packages and frontend testing references across `mta-test-design`, `mta-build`, and `mta-run-analyze`.

---

### Upgrading / Migration Notes
No breaking changes. Run `npm run update:skills` and `npm run update:tools` to ensure your local linter and skills are up to date.
