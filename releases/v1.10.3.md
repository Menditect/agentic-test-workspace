### Detailed Changes
- **Expanded Execution Plan Validation Rules (`tools/mta-lint.mjs`)**:
  - **ANTI-03 (Piped Retrieve Single Object Count Verification)**: Enforces that any piped `RetrieveObject` step (`Input Handle != '-'`) retrieving a single object embeds an `Assert Object Count == 1` check to guarantee deterministic handle assignment.
  - **ANTI-53 (Zero Unparsed Date Macros in Payloads)**: Scans parameter bindings, payloads, and initial values to prevent unparsed Mendix runtime date macros (such as `[%CurrentDateTime%]`, `[%BeginOfCurrentDay%]`, `[%EndOfCurrentDay%]`) from being authored directly into test steps.
  - **PAT-94 & ANTI-45 (Mandatory DatePicker Format Model Extraction)**: Enforces that frontend plans targeting DatePicker widgets document verified `CustomDateFormat` patterns extracted from the model (`mxcli bson dump`) and forbids guessing or defaulting date formats.
- **Enhanced Smoke Audit (Phase 6 Parity Check)**:
  - Added **Phase 6: DateTime & DatePicker Configuration Parity** to the automated smoke audit (`mta-lint audit`), verifying that server-side test steps are free of unparsed date macros and that DatePicker steps maintain format documentation and parameters.
- **Fixture Suite & Self-Test Expansion**:
  - Added test fixtures in `tools/fixtures/`: `invalid_piped_retrieve_no_count.md`, `invalid_datepicker_no_format.md`, and `invalid_date_macro.md`.
  - Updated `tools/fixtures/valid_frontend_plan.md` to demonstrate compliant DatePicker format documentation.
  - Expanded internal linter self-test suite to **17/17 passing tests**.
- **Upstream Tool Sync**:
  - Updated `scripts/sync-upstream.js` to distribute the new test fixtures across consumer workspaces.
